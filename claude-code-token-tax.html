THE HARNESS · What actually gets sent

The model never sees
"just your prompt"

Claude Code is a harness: a loop that assembles a full API request, sends it, executes any tool calls the model asks for, appends the results, and sends everything again. The system prompt and every tool definition get re-sent on each round trip, because the model remembers nothing between calls.

This costs you twice. Money: input tokens are billed per request, and caching softens that without erasing it. Attention: everything the model reads past is noise sitting between it and your problem. Trimming irrelevant context usually improves output quality too.

THE DENY LIST · permissions.deny, what & why

Deny by name,
and the schema vanishes

Put a bare tool name in permissions.deny and its whole definition drops out of the payload. The model never sees it. Here is each entry in the config, what the tool does, and why it earned removal:

Planning & interaction
EnterPlanMode / ExitPlanModeToggles for plan mode, where the model drafts a plan for approval before touching code.
Why denyTwo schemas plus their instructions, wasted tokens if you review diffs instead of plans. Keep them if plan mode is part of your flow.
AskUserQuestionLets Claude pause and present structured multiple-choice questions mid-task.
Why denyIf you steer with plain follow-up messages anyway, the interactive-prompt machinery is unused schema on every turn.
Niche editors & integrations
NotebookEditEdits Jupyter notebook (.ipynb) cells. A specialized editor with its own large schema.
Why denyUnless you work in notebooks, it's one of the larger single tools you'll never call.
DesignSyncSyncs with design tooling so Claude can pull design context into coding tasks.
Why deny~2k+ tokens of schema; irrelevant to any workflow that doesn't touch design files.
Background & remote machinery
SendMessageMessaging between agents/sessions in multi-agent and background runs.
Why denyOnly earns its tokens if you run multi-agent workflows. Solo interactive coding never calls it.
PushNotificationSends push notifications to your devices about session events.
Why denyYou're sitting in the terminal; you don't need Claude to text you about it.
RemoteTriggerLets sessions be triggered or driven remotely (e.g. from another device or service).
Why denyThis only exists for remote control. If your sessions start when you type, it does nothing.
ReportFindingsStructured reporting channel used by background / monitoring-style runs to file results.
Why denyInteractive sessions report findings the normal way: in the reply.
ScheduleWakeupSchedules a future wake-up for a background agent to resume work.
Why denyMeaningless outside long-running background jobs.
Scheduled tasks
CronCreate / CronDelete / CronListCreate, remove, and list recurring scheduled tasks that run Claude on a timer.
Why denyThree schemas for a feature most people never enable. If you don't schedule runs, cut all three.
⚠ Bare vs scoped: the detail that matters"NotebookEdit" removes the tool from the payload. "Bash(rm *)" or "Skill(dataviz)" blocks the matching call but leaves the full definition in the request. To shrink tokens, use bare names. Scoped rules are for safety, not size.
FEATURE FLAGS · One switch, whole cluster gone

Flags cut whole features.
Deny rules cut the rest.

Some features bring a whole bundle of tools and instructions. A single top-level flag in settings.json removes everything the feature carries. Use flags for the broad first pass, then deny rules to pick off what's left.

disableWorkflowsbiggest single win
Removes the multi-agent Workflow tool, typically the largest single line in the payload (~5.3k tokens of schema alone). Keep it only if you actually orchestrate multi-agent runs.
disableBundledSkills
Removes all of Anthropic's bundled skills from the catalogue Claude reads, while their slash commands stay typable. This one is all-or-nothing; for per-skill control see skillOverrides (Sheet 06).
disableRemoteControl
Strips the machinery for controlling sessions from other devices. Pairs naturally with denying RemoteTrigger / PushNotification.
disableClaudeAiConnectors
Removes claude.ai connector integration (Drive, Gmail, etc. reaching into your coding session). If your coding agent doesn't need your calendar, cut it.
disableArtifact
Removes the Artifact tool, which publishes session output as a private web page on claude.ai. Rarely wanted from inside an editor.
FIELD TRICKS · 1 of 6

See exactly
what ships

Claude Code talks to the API over plain HTTP, so you can put a small logging proxy in between. Every request gets saved as a readable file, and a table prints ranking every tool by size. Now you cut based on facts, not guesses.

# one file, no dependencies $ node proxy.mjs # point Claude Code at it in another terminal $ ANTHROPIC_BASE_URL=http://localhost:8787 claude

/context gives you one number for all tools together. The proxy tells you which single tool is the biggest, so you know exactly what to remove.

FIELD TRICKS · 2 of 6

Keep some skills,
drop the rest

disableBundledSkills removes every skill at once. If you want to keep a few, use skillOverrides instead. Set a skill to "off" to remove it completely, or "user-invocable-only" to keep its slash command typable while Claude no longer reads its description on every message.

// in settings.json "skillOverrides": { "dataviz": "off", "review": "user-invocable-only" }
FIELD TRICKS · 3 of 6

Remove MCP servers
you don't use

Every MCP server you register loads its tool descriptions when a session starts, whether you ever call them or not. Open ~/.claude.json and your project's .mcp.json and remove anything you haven't touched in two weeks. Adding one back later takes a minute.

For many people this saves more tokens than all the built-in trimming combined. If you run several servers, check this first.

FIELD TRICKS · 4 of 6

Cap the
thinking budget

Thinking tokens are billed as output, and output is the expensive side. Without a cap, the model can spend freely even on easy tasks. Around 10,000 is enough for most work, with no drop in quality on routine tasks.

// in settings.json "env": { "MAX_THINKING_TOKENS": "10000" }

Raise it for a single session when a problem truly needs deep reasoning, then put it back.

FIELD TRICKS · 5 of 6

Keep CLAUDE.md
short

Your memory files are pasted into every single message, word for word. A 2,000-token CLAUDE.md is a 2,000-token charge on every turn, all day. Keep only short rules that Claude actually needs every time.

Move long docs and reference material into normal files in the repo. Claude can open them when a task needs them, and they cost nothing the rest of the time.

FIELD TRICKS · 6 of 6

Watch the
history grow

Every file Claude reads and every command result stays in the chat for the whole session. By message 40, each new turn is re-paying for messages 1 to 39. The window fills quietly while you work.

Start a fresh session for each task and the meter resets to your small baseline. This habit alone beats most settings changes.

THE LAST 5.6K · What remains after trimming

The last 5.6k,
and the real costs now

What remains is 2.4k of core system prompt (identity, safety, environment; you can't reduce this) and 3.2k of core tools, the file, search, and shell toolkit that makes Claude Code useful. You can still shave a little. But past this point, the money is elsewhere: in the chat itself, and in which model you use. The next four sheets cover both.

THE LAST 5.6K · 1 of 4

A few more tools
can go

If you truly never use them, deny these by bare name too: WebSearch and WebFetch (Claude browsing the web), TodoWrite (the visible task list), and Task (starting subagents; keep it if you hand work off). Worth maybe another 1–2k.

// add to the same deny list "deny": [ ..., "WebSearch", "WebFetch", "TodoWrite" ]
THE LAST 5.6K · 2 of 4

Leave the core
tools alone

Bash, Read, Edit, Write, Glob, and Grep stay. Removing them saves a few hundred tokens and makes the agent much worse: it falls back to slower workarounds or simply fails at the task. Here's what each one actually does:

BashRuns shell commands: build, test, git, scripts, anything the terminal can do.
Why keepCut it and Claude can't run your tests, git, or build. The agent goes blind.
ReadOpens a file, image, PDF, or notebook so Claude can see its contents.
Why keepWithout it Claude can't look at your code before changing it.
EditMakes an exact find-and-replace inside an existing file.
Why keepThe precise way to change code; removing it forces slow full-file rewrites.
WriteCreates a new file or overwrites one completely.
Why keepNeeded for new files; without it Claude can only patch what already exists.
GlobFinds files by name pattern, e.g. **/*.ts.
Why keepHow Claude locates files fast; cut it and it falls back to slow shell hunting.
GrepSearches inside files by regex, ripgrep-fast.
Why keepFinds where code lives without reading whole folders into context.

The goal of trimming is to remove noise, not to take away the tools that do the actual work.

THE LAST 5.6K · 3 of 4

Your cost curve
is now the chat

At 0.56% of a 1M window, the fixed overhead problem is solved. What grows now is the conversation itself: every file read and every result stays for the whole session, and each new turn re-pays for all of it.

Short sessions and a clean context are now worth more than any further settings change. The 1M chapter ahead shows the math.

THE LAST 5.6K · 4 of 4

Pick the model
by the job

You're on Opus 4.8, which has premium per-token rates, and requests past 200k input can bill at higher long-context prices. Send routine edits to Sonnet and save Opus for architecture and hard multi-file bugs.

This one habit saves more money than any further baseline cut. Rule of thumb: baseline is fixed cost, history is the running cost, model choice is the multiplier.

THE 1M CONVERSATION · Why long sessions cost 40x

You don't pay for 1M once.
You pay for it every turn.

A chat model is stateless: each turn re-sends the entire growing history. Let a session grow to 1M context over ~100 turns and the total input lands around 50M tokens, not 1M. The same "1M-token session" produces wildly different bills:

Order of magnitude to remember: the baseline trim saved ~$0.11 per turn. The habits on the next six sheets save hundreds per session.

THE 1M CONVERSATION · Habit 1 of 6

One task,
one session

The cheapest context is the one you never build up. Finish a task, then start fresh. A new session resets the meter to your small baseline instead of dragging hundreds of thousands of dead tokens into every new turn.

If you feel the urge to say "new topic, but while I have you here...", that's the moment to open a new session instead.

THE 1M CONVERSATION · Habit 2 of 6

Clear early,
compact at milestones

/clear wipes the history between unrelated asks. /compact summarizes it into a short recap so you can keep going. Run /compact at a good stopping point, like when tests pass or a feature is done.

Don't wait until the window is 90% full. A calm, early compact keeps what matters. A forced one in the middle of a task can lose the thread.

THE 1M CONVERSATION · Habit 3 of 6

Write a
handoff note

Before ending a long session, ask Claude to write a short note (decisions made, the file map, next steps) into a scratch NOTES.md. The next session reads a 1k-token summary instead of inheriting 400k of old transcript.

> Before we stop: write NOTES.md with what we decided, which files changed, and what's left to do.
THE 1M CONVERSATION · Habit 4 of 6

Read only
what you need

Every file Claude reads lives in the context for the rest of the session. Point it at specific files and line ranges. Let it Grep for the relevant part instead of opening whole folders.

Never paste a huge log into the chat. Save it to a file and ask Claude to search it. Same answer, a fraction of the tokens.

THE 1M CONVERSATION · Habit 5 of 6

Let subagents
take the mess

Everything a subagent reads and runs disappears when it finishes. Only its summary comes back to your main chat. Hand noisy research ("find where auth is handled") to a subagent, and the mess never enters your context at all.

THE 1M CONVERSATION · Habit 6 of 6

Protect
the cache

Caching is what turns a $525 session into $60, but it only covers the part of the request that hasn't changed. After the first message, your baseline is re-read at about a tenth of the price on every turn.

Editing settings, CLAUDE.md, or MCP config in the middle of a session breaks the cache, and the next turn re-pays for the whole context at full price. Change settings between sessions, not during.

CAP WHAT COMES IN · Tool replies and command output

Put a limit on
what tools can dump

The deny list shrinks what ships at the start of every message. But most of the pile-up happens during the chat: tool replies and command output land in the window and stay there for the whole session. Three caps stop the flood at the door.

01

Cap MCP replies

The default limit per MCP reply is 25,000 tokens, and each one sits in your chat until the session ends. Lower it.

"env": { "MAX_MCP_OUTPUT_TOKENS": "8000" }
02

Cap command output

When a command prints more than this limit, Claude Code cuts it short and adds a small notice instead of pasting everything.

"env": { "BASH_MAX_OUTPUT_LENGTH": "30000" }
03

Filter with hooks

A PreToolUse hook can compress command output before Claude sees it. Tools like RTK cut 60–90% on common commands, or pipe through grep and tail yourself.

COMPACTION · The window is smaller than it looks

Control the squeeze
before it controls you

Claude Code compresses your chat when it gets full. Left alone, it does this late, quietly, and on its own terms. Three facts change how you use it:

your usable space
auto-compact fires here (~84%)
~33k reserved
you never get this
01

Compact earlier

Waiting until ~84% means compacting mid-task with a stuffed window. One test found compacting near 60% performed up to 39% better than waiting. Set your own trigger:

"env": { "CLAUDE_AUTOCOMPACT_PCT_OVERRIDE": "70" }
02

Tell /compact what matters

It takes instructions. Say what to keep and what to throw away instead of accepting the generic summary. Run it at a good stopping point, like when tests pass.

/compact keep the auth changes,
drop test output
03

The quiet clearing

On long chats, Claude Code also clears old tool results with no message shown. Don't count on an old file read still being there. Save important findings to a notes file as you go; a notes file survives, context may not.

One catch: DISABLE_AUTO_COMPACT only turns off the big auto-compact. The quiet clearing still runs either way. You can steer the squeeze, but you can't fully switch it off.

ONE-SHOTS · claude -p answers and exits

Quick questions don't
deserve a session

Not every question needs a chat. claude -p (print mode) takes one prompt, answers, and exits. Nothing is stored, nothing piles up, and the next question starts from zero instead of paying for everything before it.

# ask about an error, get an answer, done $ claude -p "what does ECONNREFUSED mean in a Node app?" # pipe files or output straight in $ cat build.log | claude -p "why did this build fail?" $ git diff | claude -p "review this change, list problems only" # use it inside scripts $ claude -p "write a one-line commit message for this" < staged.diff # answers, exits. Nothing carried into any session.

Asking inside a session

A 50-token question asked at 300k context costs 300k+ input tokens, and its answer keeps costing on every turn after.

Same question costs a few thousand tokens once. Your real session stays clean and cheap.

Rule of thumb: if the answer won't change what you do in the current session, ask it with -p in another terminal. Error meanings, syntax questions, quick reviews, commit messages: all one-shots.

CHEAP HELPERS · 1 of 3

Small, cheap
subagents

Define agents in .claude/agents/ with a short tools: list and a cheaper model. The digging happens on Haiku or Sonnet with a small toolset, and only the summary returns to your main chat, where the expensive model works.

# .claude/agents/repo-scout.md --- name: repo-scout tools: Read, Grep, Glob model: haiku --- Find and summarize. Return under 300 words.
CHEAP HELPERS · 2 of 3

Check before
pruning MCPs

Newer versions of Claude Code load MCP tool descriptions on demand once they would take more than about 10% of the window, instead of loading everything up front. So before you spend an evening pruning servers, look at /context: some of yours may already cost very little.

CHEAP HELPERS · 3 of 3

Flags that only
touch your bill

Three small levers that save money rather than context. CLAUDE_CODE_DISABLE_1M_CONTEXT=true keeps you on the normal window, away from long-context prices, if you don't need 1M. DISABLE_NON_ESSENTIAL_MODEL_CALLS=1 skips small background model calls for things like chat titles. And CLAUDE_CODE_MAX_OUTPUT_TOKENS limits how long a single answer can be.

Then run /cost at the end of a session to see what it actually spent. Change one setting at a time and compare. Numbers beat guesses.

A menu,
